# Коды ЧЗ — выгрузка на терминал (Flutter, Windows)

## Общая история на файловом сервере

История выгрузок хранится на сетевой папке — её видят все пользователи.

```
\\192.168.2.11\obmen\Работа\HonestSignManager для весовых терминалов\
├── store\
│   ├── records\2026\20261026-081500-4f2a.json   ← одна выгрузка = один файл
│   └── tombstones\20261026-081500-4f2a.json     ← отметка «удалён»
└── (локальный кеш каждого пользователя хранится в его профиле)
```

Файлы записей создаются один раз и после этого никогда не меняются,
поэтому несколько человек могут работать одновременно без конфликтов.

Локальный кеш (`%APPDATA%\...\cache.db`) служит только для скорости:
его можно удалить, он построится заново из файлов на шаре.

### Если шара недоступна

Приложение продолжает работать:
- история показывается из локального кеша;
- выгрузка на терминал не блокируется — запись сохраняется локально
  и автоматически досылается на шару при следующей синхронизации;
- сверху появляется предупреждение, что данные могут быть неполными.

### Синхронизация

Происходит автоматически при открытии вкладки «История» и перед выгрузкой.
Кнопка «Обновить» — принудительно. Внизу показано время последней синхронизации.

```
.\build_release.bat
```

Шаги: `clean` → `pub get` → `analyze` → `test` → `build windows --release` → упаковка.

| Папка для запуска | `dist\HonestSignManager\` |

## Раздел «Остатки»

Показывает по выбранному товару и терминалу:

- **свободные коды** — `GET /codes/{productId}/count`, статус NEW;
- **напечатанные** — из `GET /labeling-history` со статусом Ready;
- **загруженные, но не напечатанные** — коды из нашей истории выгрузок,
  которых нет среди напечатанных;
- **отменённые (Cancelled)** и **в обработке (Locked)**.

### Важная особенность API

В `GET /v1/honest-sign/labeling-history` **нет фильтра по товару** — только
`exportStatus`, `skip`, `take`, `createdAtAfter`. Поэтому история забирается
страницами по 1000 и фильтруется по `productId` уже на клиенте. Для этого
и сделан выбор периода: чем шире период, тем больше страниц нужно скачать.

`productId` берётся из `honestSignCodeMeta.productId`, если там пусто —
из `product.id`. Записи, где товар определить не удалось, считаются
отдельно и показываются в сводке, чтобы не терялись молча.

### Проверка сходимости

В сводке есть строка «Свободные коды минус незапечатанные»:

- **0** — данные сходятся;
- **больше 0** — на терминале есть свободные коды, загруженные не через
  это приложение (или с другого компьютера);
- **меньше 0** — часть ранее загруженных кодов уже израсходована,
  напечатана не полностью, или удалена с терминала вручную.

### Отчёт Excel

Кнопка «Отчёт в Excel» создаёт книгу из трёх листов:

| Лист | Содержимое |
|---|---|
| Сводка | Товар, терминал, период, все счётчики, проверка сходимости |
| История маркировки | Код ЧЗ, Base64, статус, даты, партия, сроки, веса, принтер |
| Не напечатаны | Коды из нашей истории, не найденные среди напечатанных |

Файл пишется своим writer'ом (`xlsx_writer.dart`), без сторонних пакетов.
Кириллица, длинные коды и `&<>"'` экранируются корректно; управляющие
символы, на которых Excel ругается, вырезаются.

## Проверка связи с терминалом

На вкладках «Выгрузка» и «Остатки» рядом с полем адреса терминала есть кнопка
**«Проверить связь»**. Она отправляет один GET-запрос на адрес терминала с
таймаутом 5 секунд и сообщает результат:

- **«Терминал в сети (HTTP …)»** — терминал ответил, даже если кодом 404.
  Для 404 приложение дополнительно напоминает проверить путь `/api`.
- **«Терминал не отвечает (таймаут подключения)»** — ответа не было вовсе:
  неверный IP или порт, терминал выключен, или он не в той же сети.

Кнопка ничего не загружает и не удаляет: это только проверка доступности.
Если терминал появляется в сети нестабильно, проверка может сработать не с
первого раза — тогда её можно повторить.

Адрес вводится в виде `http://IP:порт/api`, например `http://192.168.1.163:4001/api`.
Если указать только `IP:порт`, приложение добавит `http://` само, но путь
`/api` нужно указать явно.

## Изъятие и возврат кодов

Терминал не даёт менять справочник товаров, пока на нём есть загруженные
коды. Поэтому коды снимаются в файл (`vault/<id>.json` локально и
`store/withdrawals/<id>.json` на файловом сервере), товары правятся, коды
возвращаются кнопкой «Вернуть».

### Что было не так (исправлено)

После цикла «изъять → вернуть» на терминале оказывалось **больше** кодов,
чем было до изъятия: например, было 980, стало 1000. Лишние 20 — это
дубликаты маркировки.

**Причина.** Список кодов для изъятия строился по истории выгрузок
приложения, то есть по всему, что когда-либо было загружено на терминал.
Часть этих кодов терминал уже напечатал на товаре (статусы `Ready`,
`Locked`, `Cancelled` в истории печати), и свободными они больше не были.
Приложение этого не знало: оно писало такие коды в файл изъятия, а при
возврате загружало обратно как новые. Напечатанные коды снова становились
свободными и могли быть нанесены на товар повторно.

### Как работает теперь

**Изъятие.** Перед снятием приложение запрашивает у терминала историю печати
(`GET /v1/honest-sign/labeling-history`, все статусы) и делит коды из истории
выгрузок на две группы:

- **свободные** — снимаются с терминала и сохраняются в файл изъятия, потом их
  можно вернуть;
- **напечатанные** — тоже удаляются с терминала, но в файл не пишутся и не
  возвращаются.

Повторы одного кода в истории выгрузок попадают в файл один раз.

**Почему напечатанные коды тоже удаляются.** Пока на терминале остаётся хоть
один код товара, терминал не даёт удалить этот товар. Импорт справочника
падает с ошибкой 500:
`delete on table "product" violates foreign key constraint ... on table "honest_sign_code"`.
В первой версии исправления напечатанные коды оставались на терминале: после
изъятия на нём было 2126 таких кодов, и правка товаров не проходила. Теперь
они удаляются, а дубликатов при возврате нет, потому что в файле их нет.

Удалённые напечатанные коды помечаются в локальной базе
(`codes.status = 'printed_deleted'`), чтобы следующее изъятие не пыталось
удалить их снова.

**Если напечатанные коды остались после прошлого изъятия**, нажмите «Снять все
коды в файл» ещё раз. Приложение удалит только оставшиеся напечатанные коды.
Свободных кодов на терминале уже нет, поэтому новый файл изъятия не создаётся.
Записи в статусе «Изъят» продолжают учитываться, поэтому такой повторный
проход работает.

Если удалить напечатанные коды не удалось (ошибка терминала посреди удаления),
свободные коды всё равно остаются в файле изъятия. Сообщение будет красным —
повторите изъятие, и оно удалит только оставшиеся напечатанные.

**Ограничение периода истории.** Запрос истории печати идёт не за всё время
работы терминала, а начиная с самой ранней выгрузки снимаемых (или
возвращаемых) кодов, минус одни сутки. Раньше запрос брал всю историю, и
изъятие зависало на стадии «Подготовка» на терминале с большим объёмом печати.
Теперь на время загрузки истории показывается статус с числом записей.

**Возврат.** Приложение повторно сверяется с историей печати и не загружает
коды, которые напечатаны за время между изъятием и возвратом. Благодаря этому
защищены и **файлы изъятия, созданные до исправления**: в них уже лежат
напечатанные коды, и при возврате они будут пропущены с пометкой в сообщении.

**Обрыв при возврате.** Если связь оборвалась посреди возврата, принятые
терминалом коды запоминаются (`<id>.progress.json` рядом с файлом изъятия).
При повторе они не загружаются второй раз. Раньше повтор после обрыва
создавал дубликаты.

**Если историю печати получить не удалось** (терминал не отвечает, ответ
неполный или история слишком большая), изъятие и возврат **не выполняются**,
ничего не удаляется и не загружается. Отличить свободный код от
напечатанного без этих данных нельзя, а ошибка в эту сторону дороже простоя.

### Как сопоставляются коды

По коду идентификации — части до разделителя GS (`01` + GTIN + `21` +
серийный номер). Так сопоставление не зависит от того, пришёл код с хвостом
(серия, код проверки) или без него.

Отменённые печати (`Cancelled`) тоже считаются использованными и не
возвращаются. Так сделано намеренно: потерянный код лишь не будет
использован, а возвращённый напечатанный — нарушение маркировки. Если
понадобится возвращать и такие коды, это одна строка в `_fetchUsedKi`
(`lib/services/vault_service.dart`).

### Что нужно знать

- Коды, загруженные на терминал не через это приложение, оно не видит и не
  удаляет. Если после изъятия импорт товаров всё равно падает с той же
  ошибкой 500, на терминале остались такие коды.
- Удаляются ли на терминале записи истории печати вместе с напечатанными
  кодами, не проверялось: это зависит от устройства базы терминала. Первая версия
  программы удаляла все коды, включая напечатанные, так что это поведение
  не новое.

- Файл изъятия, созданный старой версией, возвращать можно: напечатанные
  коды в нём будут пропущены автоматически.
- Если после обновления на терминале уже есть дубликаты от прошлых возвратов,
  автоматически они не исчезнут: исправление предотвращает новые.
- Проверка идёт по истории печати терминала. Коды, которые кто-то удалил
  с терминала вручную мимо приложения, она не отслеживает.
- Покрыто тестами на поддельном терминале
  (`test/vault_withdraw_restore_test.dart`), в том числе сценарий «1000 в
  истории, 20 напечатаны». На живом терминале исправление не проверялось.

## Первый запуск

1. «Настройки» → токен → «Сохранить токен».
2. «Настройки» → «Импортировать из Excel» → справочник товаров (A — ID, B — наименование).
3. «Настройки» → «Файловый сервер» → проверить путь → «Проверить доступ» → «Сохранить».
4. «Выгрузка» → перетащить файл с кодами (столбец B) → адрес терминала → товар → «Выгрузить коды».

## Права на папку

Пользователям Windows нужны права **«Изменить»** на папку из `storePath`
(и подпапки). Стандартная авторизация Windows — отдельные учётные данные не нужны.

## API терминала

| Действие | Метод | Путь | Тело |
|---|---|---|---|
| Загрузка | POST | `/v1/honest-sign/codes/bulk` | `{"bulk":[{"code":"<base64>","productId":77}]}` |
| Удаление | DELETE | `/v1/honest-sign/codes/delete/bulk` | `{"codes":["<base64>", ...]}` |

Заголовок: `Authorization: Bearer <токен>`. Путь добавляется к введённому адресу как есть.
